# 0.3.1 本地候选版与发布边界

## 当前能力

- Codex / Claude Code / WorkBuddy：安装观察型 Hook 后接收事件；普通 Claude Chat 不在范围内。权限检查不等于用户审批，明确需要输入的通知回原应用操作。
- 豆包：只读本地 Agent 轨迹的角色、工具类别、mtime；普通聊天、批准、停止、回复不支持。未知角色/静默不伪造完成，停止跟踪不表示任务中断。
- 120Hz 仅是弹簧采样频率，不保证显示器实际 120FPS。相同布局/宽度不重复发布，任务衍生数据缓存，事件增量在后台读取解析。
- 自动适配与手动活动宽度明确分开；空闲态始终物理刘海，摄像头安全下限优先；设置显示实际大小。
- “今日活跃轮次”为保留记录中今日收到更新的任务轮次，不是模型/API 调用次数，也不是新建任务数。删除显示记录会改变统计。
- 24 小时是可见窗口，不是数据保留期限；原始日志保留用于恢复。每批最多 1MiB / 256 行，未完成一行留到下次读取，不自动轮转、不自动删除历史。

## 可重复的本地流程

1. `bash script/check_sandbox.sh`：重新编译全部源码，隔离目录验收，不扫描个人豆包轨迹或会话标题数据库。
2. `./script/build_and_run.sh --verify`：Debug 本地体验。设置页版本与包中源码 SHA256、Git 状态关联；版本来自 `VERSION`，日期仅作 build ID。
3. `./script/build_and_run.sh --release-package`：Release 构建至 `dist/Release/Agent 灵动岛.app`，避免并行Debug打包覆盖；打包 HUD、CLI 和安装器，不自动启动、不修改用户 Hook；`--release-verify` 可重启本地 Release 候选版。包使用本地 ad-hoc 完整性签名，不访问证书、不等于 Developer ID 可信分发。
4. `bash script/check_release.sh`：包结构、版本、源码指纹、依赖、签名与公证状态诊断。此步骤只读取；结构合格不代表可分发。

安装器默认 dry-run，`--apply` 需要用户主动选择，会保留其他配置并备份；`--uninstall --apply` 仅移除本项目命令。包内安装器依赖本机 Python 3，当前未提供无需命令行的首用向导，因此候选版仍面向个人体验。退出或卸载 HUD 不会停止厂商任务。不得自动删除 `events.jsonl` 或 `hook-turns.json`，两者的恢复游标互相关联。

## 对外发布阻断项

- Developer ID 签名、hardened runtime、公证/staple 尚需用户确认证书与分发方式；未提交公证、未上传发布。
- 三家厂商版本兼容性必须使用真实当前版本验证；Claude Code 此前正常请求被账户 401 阻挡，不能拿模拟回调替代验证。
- 真连续 hover、屏幕物理刘海合缝、120FPS、快速逆转、不同屏幕、锁屏/解锁与睡眠恢复需要真机证据。自动化状态/数学测试通过不等于这些项目通过。
- 首用接入向导、可选登录启动、明确的可恢复日志归档策略仍是后续产品化工作，当前不隐式开启或删除数据。

未验证项目应保持 NOT VERIFIED，不能据此宣称“公开发布已验收”。
