# 批准流程提速：快捷键 + 直达（2026-10-11，L2）

## 改了什么
- 点击「待批准」会话行：直接打开批准弹窗（原来要先选中 → 详情 → 「批准请求…」）。行内新增「批准…」标记。
- 批准弹窗快捷键：`⌘↩` 仅允许这一次，`⌘⌫` 拒绝本次，`Esc` 关闭（不做决定）。按钮上显示键位。
- 全局快捷键 `⌃⌥A`：仅在存在待批准请求且灵动岛可见时注册，只负责「打开批准弹窗」，不会直接批准。
- 弹窗参数改为逐字段展示（command / path 等优先），所有参数仍完整展示；解析失败回退为原始 JSON。

## 第二轮：自动打开 / 来源 / 风险提示
- 设置「收到批准请求时直接打开批准窗」（默认关；`--auto-open-approval` 可在单次启动时开启）：每个新请求只自动打开一次，Esc 关闭后不会重复弹出；仍需 `⌘↩` 才批准，沿用 0.6 s 防误触。代价：占用键盘焦点，打字时可能被打断。
- 批准窗顶部显示「来自：任务名 · 工作目录」。
- 高风险片段提示（`ApprovalRisk`，仅提醒、不拦截、不替你决定）：递归删除、sudo、强制推送、`git reset --hard` / `clean -f`、下载后直接执行、`chmod 777/-R`、磁盘级操作、删库表。命中时顶部红色提示，命令中对应片段标红。属启发式，未命中不代表安全。

## 安全约束（未改变）
- 先展示完整参数，才能选择允许/拒绝；协议 v2、单次、45 s 过期、不返回 `updatedPermissions` 均未改动。
- 仅 Claude Code；Doubao / Codex 仍不可在灵动岛批准。
- 决定键为 `⌘` 单独修饰、忽略长按重复；弹窗打开后 0.6 s 内忽略决定键，避免发给别的应用的按键误批。
- 刻意未做「低风险一键批准」：会改变文档化的安全模型（L3），需另行决定。
