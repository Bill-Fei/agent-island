# L3：升级接入连续性与 AI 工作时长

## 范围

- 三家固定入口、已有旧 Hook 配置迁移、缓存旧桥持续维护、原生/Python 路径一致。
- 保留外部配置与 Claude 单次审批选择；启动不添加/重新启用缺失接入。
- 配置与桥接检查、未知协议 metadata-only 诊断、不把无回调当断连。
- 展开态底部的今日 AI 工作时长，不改变小态、刘海几何、任务优先级。

## 统计边界

只统计三家 Hook 的可确认执行区间并集；等待不计入。未闭合尾段、轮次歧义、日志损坏、协议未知和 >30 分钟事件空档不推算。是保守下界，不是注意力计时；豆包/Claude Chat 不在当前覆盖范围。统计保留本机时区跨午夜裁剪，不上传日志正文、输入或凭据。

## 验证记录

- SwiftPM 正常构建通过。
- 完整 contained validation 已通过（Shared、TaskStore、后台检查点、三家 Hook、Claude 单次审批）。新增时长覆盖并行、等待、跨日、迟到事件、终结防复活、损坏断点；原生安装覆盖二次升级与缓存旧桥。
- Python 隔离安装验证固定入口、两次升级缓存旧桥、保留 foreign setting/Claude relay，以及只改所选 provider。
- 独立只读源审：阻断项已修复，最终无剩余发布阻断；主动忽略事件的健康误报建议也已修正。
- 真机 UI、最新打包启动及真实 Hook 验证结果待后续记录；不以隔离 fixture 当 provider end-to-end。

## 已知边界

第三方配置没有共享 CAS/锁协议；写入前复核缩小覆盖窗口但不能保证绝对无竞态。第三方破坏性协议变化只能明确降级和提供恢复入口，不能承诺任意未来更新永远兼容。老 App 同时启动可能刷新桥接回旧版本，避免并行运行多个版本。
